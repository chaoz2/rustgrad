# tinygrad compatibility ledger

This ledger is RustGrad's release gate. "Feature complete" means observable capability and semantics compatible with the checked-in tinygrad revision, not identical Python APIs or files.

Status: ✅ verified · 🚧 partial · ⬜ not started · 🚫 user-approved exclusion. No item becomes ✅ without an automated acceptance test; exclusions require an explicit user decision.

Validation note: reduction semantics are covered by RustGrad regressions against the checked-in tinygrad implementation and tests. A live tinygrad differential run is still unavailable in this workspace because tinygrad reports no usable device; this is an environment-validation gap, not an unimplemented reduction semantic.

# CPU scalar C JIT

The first native JIT supports static scalar-domain fused elementwise kernels:
range/index/load/store, broadcasting, integer constants, casts, select,
comparisons, guarded exact integer division/modulo/shifts, bitwise basic ALU,
and add/sub/mul/div/floor-div/trunc-div/mod/fmod/min/max plus
neg/abs/square/relu/sqrt/rsqrt/exp/reciprocal. F16 and BF16 are
loaded from raw `u16` storage into scalar `f32` and encoded back with deterministic
half/bfloat rounding helpers. Native failures return a status plus linear index;
they never invoke C divide-by-zero or invalid-shift behaviour.

Static sum, mean, product, and typed minimum/maximum reductions are also native:
one checked `NativeReductionPlan` derives normalized geometry, source,
accumulator, and output storage from the exact scalar
`ReduceInit → ReduceAccumulate → ReduceFinalize` chain. CPU, captured replay,
C11, PTX, OpenCL, Metal, and WGSL consume that plan rather than reconstructing
the recurrence. Every update commits at accumulator width; extrema begin at
the committed dtype identity and retain it on ties or unordered comparisons,
while an effective singleton reduction bypasses recurrence and preserves its
lane. Mean commits its count and division at F32 or F64 work width and returns
canonical NaN for an empty domain without issuing a divide. Raw/explicit
same-storage Sum remains distinct from tinygrad-facing typed Sum, whose
accumulator selection and final narrow cast stay in the public graph layer.
Historical RGUA reduction tags, payload bytes, and durable v18 schedule
identities remain unchanged. Corrected compiled kernels cannot collide with
the former recurrence because every affected renderer/source cache version is
bumped independently.
PTX and OpenCL retain their proven dtype/capability subsets; Metal is limited
to F32/Bool/I32/U32 and WGSL to F16/BF16/F32/Bool/I32/U32. Symbolic extents,
true vector-reduction lanes, Float8 device reduction, and parallel reduction
algorithms remain rejected before backend resource work.

Materializing movement roots use a separate validated payload rather than a
model-specific kernel: concat copies exact storage in output-coordinate order;
gather and scatter validate every integer index before exposing an output;
replacement scatter uses deterministic last-row-major-write semantics; and
F32/F64 scatter-add accumulates in row-major order. These kernels retain first-
use operand bindings, serialize exactly with the captured schedule, and execute
from deserialized artifacts without reconstructing the source Graph.

`compile_specialized` accepts the existing symbolic planning shapes and a full
binding map, validates variable identities/bounds/no extras, binds checked
concrete extents, and requires those domains to match the lowered ABI. Its cache
identity includes symbolic structure, variable identities, and binding values;
this is compile-time specialization, not a runtime-polymorphic C kernel.

`CpuSymbolicProgram` is the separate owned runtime-polymorphic CPU boundary for
one authenticated, effect-free bounded-symbolic `CapturedSchedule`. It renders
and lazily publishes one immutable native body whose identity includes the
capture and schema but excludes invocation values. Each invocation validates
canonical I64 parameters, guards, exact external descriptors, specialized views,
and an exact `MemoryPlan` before native preparation, then executes temporary
lifetimes through that plan's exact-compatible private slots and returns detached
ordered outputs. Program publication and its local compilation count are atomic;
a failed later native load may still leave an ordinary process-wide compiler
cache entry for an earlier kernel, and no stronger cache transaction is claimed.
The proven subset is scalar elementwise work, affine/Contiguous copies,
static-axis reductions, and dense F32/F64 Matmul; zero/scalar geometry and a
bounded RMSNorm-plus-TransformerBlock attention/FFN inference reuse the same
compiled body.

The CPU JIT also has a deterministic 16-byte portable lane policy for contiguous
elementwise kernels: 16 lanes for byte storage, 8 for `u16`, 4 for `u32`/F32,
and 2 for 64-bit storage. It emits a lane main range and isolated scalar tail;
this is deliberately an unrolled portable C representation, not an alignment-
sensitive compiler vector intrinsic. Reductions and varying broadcast offsets
remain on the scalar renderer path.

`CudaSymbolicProgram` shares that authenticated body and invocation projection.
It validates canonical parameters, guards, the complete concrete capture,
external descriptors and bytes before pure PTX/static-prefix planning and before
CUDA resource work. The first successful nonzero-work binding constructs an
explicit CUDA graph from authenticated schedule dependencies. Later
positive-work bindings with the same active topology update its exact
kernel-node function, launch, and pointer parameters without reinstantiating
the graph executable; changed topology and zero/nonzero transitions replace
it. A successful zero-work identity instead caches a resource-free
specialization. The generic device transaction caches only the last fully
successful specialization. A cache miss publishes its new identity only after
execution and ordered projection succeed; pre-update failure preserves the
prior specialization, while a partial update or cached execution failure evicts
the entry after the existing CUDA fence/poison/quarantine path.
The default program owns its PTX cache, and `with_cache` permits explicit sharing
through an `Arc<ConcurrentPtxCache>` without an ambient registry. This is
mock-driver evidence, not a live CUDA/toolkit claim.

There is still no target SIMD/vector-instruction lowering, topology-changing
CUDA graph update, symbolic OpenCL/Metal/WebGPU execution, symbolic
affine requested-passthrough sidecar, dynamic rank/cardinality,
effects/RNG/state/sharding/CALL, autograd-program construction, or broad
advanced ALU coverage. Directly requested symbolic Inputs remain supported as
source-owned values. Legacy captured symbolic replay remains checked and
concretized before native compilation. Unsupported program items are rejected
before backend compilation or allocation rather than rendered with altered
semantics.

# CUDA allocation cache phase 3B0 representation foundation

are used at the public lease boundary and PTX bindings can carry a `BufferView`.
Primary pooled physical allocations are now primary-only `PrimaryBlock` values
with retained primary identity, generation and explicit cleanup; logical leases
and views never round-trip through mixed `DeviceBuffer`. `PrimaryEventFence` is
shareable and validates its primary owner. The primary allocator now keeps
completion fences in a deferred registry and promotes completed generations
without synchronizing ordinary pooled primary PTX launches. Direct and owned-context
Primary pooled leases also support directional async peer copies through

direct buffer peer copies remain intentionally unsupported; live multi-GPU

`Graph::normalize` is a static one-axis Lp composition over existing cast, abs,
pow, sum, maximum, and division nodes. `p = 0` counts nonzero lanes; other
values use the Lp norm with an epsilon lower bound; exact and Float8 inputs
compute in F32. It adds no IR, runtime, RNG, device, or dynamic-shape path.
